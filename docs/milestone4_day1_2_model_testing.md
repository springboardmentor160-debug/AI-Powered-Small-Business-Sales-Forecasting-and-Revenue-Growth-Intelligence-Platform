# MarketMind AI: Milestone 4, Days 1-2 Model Testing

## Evaluation methodology

This evaluation scores the existing Milestone 2 forecasting and segmentation outputs. It does not retrain, replace, or modify any model.

### Forecasting

The evaluator reads `data/processed/forecast/model_validation_predictions.csv`, which contains actual values and persisted validation predictions for Prophet, XGBoost, and Random Forest. Revenue and sales quantity are scored independently with:

- **MAE:** mean absolute error.
- **RMSE:** square root of mean squared error.
- **R²:** coefficient of determination.

The artifact was checked to ensure every model for a target uses the same chronological holdout. The current holdout is 30 rows from **2025-12-02 through 2025-12-31**, following the existing 1,066-row training prefix. No future forecast rows or predictions from another test period are used.

### Segmentation

The evaluator reads existing labels from `data/processed/segments/customer_segments.csv`. It rebuilds the feature matrix using the existing `build_customer_features` helper and the same `log1p` plus `StandardScaler` preparation used by K-Means and hierarchical clustering. Customer IDs must match the persisted output in the same order. Silhouette Score is then calculated separately for the existing K-Means and hierarchical labels.

Silhouette scoring is skipped with an explicit reason when labels have fewer than two clusters, every row is its own cluster, the feature/label lengths differ, or scikit-learn rejects the configuration.

## Data used

- Forecast validation predictions: `data/processed/forecast/model_validation_predictions.csv`
- Segmentation labels: `data/processed/segments/customer_segments.csv`
- Feature sources used to reproduce the segmentation feature matrix:
  - `data/processed/sales/cleaned_sales.csv`
  - `data/processed/customers/cleaned_customers.csv`

The original datasets are read only. The consolidated results are written to `data/processed/testing/milestone4_test_results.csv`.

## Validation approach

Forecasting uses the existing chronological holdout and confirms a common date set across all available models for each target before calculating metrics. Segmentation uses the existing persisted customer ordering and labels rather than fitting new cluster models.

## Limitations

- Forecasting is evaluated on one 30-day holdout, so results may not generalize to other periods.
- R² can be negative when predictions are worse than a mean baseline; this is a valid result, not a failure.
- Segmentation validation measures geometric cohesion/separation only; it does not establish business usefulness or cluster stability.
- The persisted segmentation labels are evaluated as produced by the existing pipeline. This evaluator does not perform hyperparameter search or relabel clusters.
